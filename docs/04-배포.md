# 04. 배포

## 1차 — 로컬 실행

개인 도구이므로 배포보다 실행 편의가 우선이다.

```bash
(cd frontend && npm run build)   # ← 먼저. 결과가 src/main/resources/static/ 으로 간다
./gradlew bootJar                # 그 결과를 포함한 jar
java -jar build/libs/claude-board.jar        # http://127.0.0.1:7777
```

**프론트를 빌드하지 않으면 화면이 없는 jar 가 나온다** — API 는 뜨지만 `/` 가 비어 있다.
`src/main/resources/static/` 은 **산출물이라 커밋하지 않으므로**(`.gitignore`),
클론 직후에는 그 디렉터리 자체가 없다.

백엔드만 고칠 때는 `./gradlew bootRun` 으로 충분하다(정적 파일은 그대로 남아 있다).
프론트를 고치는 중이라면 `npm run dev`(:5173, 프록시)가 편하다 —
[06-개발환경](06-개발환경.md) 참고.

전제: **JDK 21**. `brew install openjdk@21`
(keg-only 라 PATH 에 안 잡힌다 — [06-개발환경](06-개발환경.md) 참고)

### 설치 (#35 에서 실제로 만들고 검증했다)

```bash
scripts/build.sh                    # 프론트 → jar. 화면·세션데이터 검사 포함
ln -sf "$PWD/scripts/claude-board" ~/.local/bin/claude-board
```

```bash
claude-board            # 띄운다 (이미 떠 있으면 알려주고 끝)
claude-board status     # pid·바인딩·jar 시각
claude-board restart    # jar 를 새로 빌드한 뒤
claude-board stop
claude-board log        # tail -f
```

로그는 `~/Library/Logs/claude-board/claude-board.log`.

**`scripts/build.sh` 는 두 가지를 막는다** — 둘 다 실제로 잡는 것을 확인했다:
- jar 에 화면이 없으면 실패 (프론트 빌드를 빠뜨린 경우)
- jar 에 세션 데이터가 섞이면 실패 (되돌릴 수 없는 사고)

> ⚠️ **스크립트에서 `unzip -l | grep -q` 를 쓰지 말 것.** `grep -q` 가 매치 즉시 종료해
> `unzip` 이 SIGPIPE 로 죽고, `set -o pipefail` 이 그것을 파이프 실패로 잡아
> **있는데 없다고 판정한다.** 실측으로 밟았다 — `grep -c` 는 1 을 내는데
> `if ! ... grep -q` 는 "없다"가 됐다. 목록을 변수에 담고 개수로 판정한다.

> ⚠️ **`lsof` 는 매치가 없으면 exit 1 이다.** `set -e` 와 만나면 서버가 안 떠 있을 때
> `status` 조차 못 쓴다 — `|| true` 를 붙인다. 이것도 실측으로 밟았다.

## 상시 실행 (선택)

```bash
scripts/install-agent.sh              # 등록·기동
scripts/install-agent.sh uninstall    # 제거
```

`scripts/local.claude-board.plist` 를 템플릿으로 쓰고 경로는 설치 때 채운다.

### ⚠️ launchd 는 PATH 를 물려주지 않는다

`claude` CLI 를 못 찾으면 **세션 목록이 비어 화면이 텅 빈다.**
실측 (#35) — `errors` 가 알려줬다:

```json
["agents 목록을 읽지 못함: Cannot run program \"claude\": No such file or directory"]
```

**서비스는 정상으로 보이는데 내용이 없다** — `errors` 를 노출하는 설계가 아니었으면
"세션이 없네"로 오해했을 것이다. plist 의 `EnvironmentVariables.PATH` 에
`claude` 가 있는 디렉터리를 넣는다(설치 스크립트가 자동으로 채운다).

### ⚠️ `bootstrap` 만으로는 안 뜬다

실측으로 **재현된다.** `bootstrap` 뒤에 포트가 안 열리면 `kickstart` 가 필요하다:

```bash
launchctl print "gui/$(id -u)/local.claude-board" | grep -E "state|runs"
launchctl kickstart -k "gui/$(id -u)/local.claude-board"
```

설치 스크립트가 이것을 자동으로 한다 — 포트를 최대 15초 기다렸다가, 안 뜨면 kickstart.
**3초는 성급하다**(실측: 멀쩡한 기동을 실패로 판정했다).

### `KeepAlive` 는 넣지 않았다 — 다만 "환경이 고장났다"는 아니다

⚠️ **정정 (2026-09-04).** 이 자리에는 원래
*"이 환경에서 작동하지 않는다"* 고 적혀 있었다. **그 서술은 틀렸다.**
같은 기계에서 `KeepAlive: true` 를 쓰는 에이전트 둘이 정상 동작한다:

    $ launchctl list | grep -E 'caddy|concert'
    2479  0  homebrew.mxcl.caddy          ← KeepAlive:true, 실행 중
    -     0  com.chahyunwoo.concert-watch ← KeepAlive:true

관측된 사실은 하나다 — 이 잡의 마지막 종료 코드가 **143**(=128+15, SIGTERM)이고,
`KeepAlive: true` 는 무조건 재시작이 아니라 launchd 가 **정상 종료로 판단하면
되살리지 않는다.** `kill` 로 죽여보는 검증은 정확히 그 조건을 만든다.

당시 기록은 SIGKILL 로도 안 됐다고 적었지만 근거로 든 것은 여전히 `143` 이라,
SIGKILL(137) 이 실제로 검증됐는지는 확인되지 않는다. **재현되지 않은 부분이다.**

`KeepAlive` 를 안 넣는 선택 자체는 유지한다 — 조회 전용 도구라 잠시 안 떠 있어도
손해가 없고, `claude-board start` 한 줄이면 다시 뜬다. 지금은 메뉴바 앱이
워치독을 겸한다([07-메뉴바앱](07-메뉴바앱.md)).
**다만 그 근거를 "launchd 가 고장났다"로 적지 않는다.**

로그인할 때 뜨는 것(`RunAtLoad`)까지는 동작한다.

## 2차 — 남에게 배포한다면

JVM 설치를 요구하는 게 가장 큰 마찰이다. 그때 검토할 것:

**GraalVM native-image**
```bash
./gradlew nativeCompile      # 단일 네이티브 바이너리
```
- JDK 설치 불필요, 기동 수십 ms
- 대신 빌드 파이프라인이 복잡해지고, 리플렉션 힌트를 잡아줘야 한다
- Spring Boot 3 는 AOT 지원이 있어 예전보다 수월하다

지금 하지 않는다. 로컬에서 쓸 만하다고 확인된 뒤에.

## 다기기 — 1차 범위 밖

프로·에어·맥미니에 세션이 흩어져 있다면 **중앙 서버 없이** Tailscale 로 묶을 수 있다.

```
[대시보드] ──tailnet──> 다른 기계 :7777/api/sessions
```

구현 시 주의:
- 원격용 바인딩은 `127.0.0.1` 이 아니라 **tailnet 주소로만**. `0.0.0.0` 금지
- 원격 응답은 신뢰 경계 밖. 스키마 검증 후 사용

### CI 가 자동으로 막는 것 (PR 마다)

아래 둘은 **텍스트 지시가 아니라 게이트**로 강제된다 —
CLAUDE.md 가 "되돌리기 어렵거나 조용히 번지는" 작업으로 지정한 항목이기 때문이다.

- ✅ jar 에 세션 데이터(`*.jsonl`)나 로그가 섞였는지 → 섞이면 CI 실패
- ✅ `application.yml` 에 `0.0.0.0` 바인딩이 있는지 → 있으면 CI 실패

`.github/workflows/ci.yml` 의 `backend` 잡. [06-개발환경](06-개발환경.md) 참고.

### 손으로 확인할 것
