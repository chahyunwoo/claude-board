# 00. 개요

## 문제

Claude Code 세션을 여러 프로젝트에 걸쳐 동시에 띄워두고 작업한다.
컨텍스트 관리를 위해 **프로젝트마다 일정 범위가 되면 새 세션을 여는** 방식이라
세션이 계속 쌓인다.

그 결과 지금 알 수 없는 것들:

- 어떤 세션이 **내 답을 기다리는 중**인가
- 어떤 세션이 **멈춰 있는가** (죽었거나 막혔거나)
- 각 세션이 **무슨 작업**을 하던 중인가
- **컨텍스트가 얼마나 찼는가** — 새 세션을 열 시점인가

### 실측 (2026-09-03, 맥북프로)

```
$ claude agents --json | jq length
10                       # 살아있는 세션

$ ls ~/.claude/projects | wc -l
21                       # 프로젝트

세션 기록 총 109개, 최대 파일 5.8MB      # ← 기획 시점. 구현 시점엔 총 327MB·최대 21MB
10개 중 7개가 사용자 답변 대기 상태였음
'docs-site' 세션은 27일째 떠 있음
```

`claude agents --json` 이 살아있는 세션 목록을 주지만 **무슨 작업인지·어느 브랜치인지·
답을 기다리는지는 알려주지 않는다.** 그 정보는 세션 기록 파일에 따로 있다.
이 둘을 잇는 것이 이 도구의 존재 이유다.

## 목표

1. **프로젝트 단위**로 현재 상태를 한 화면에
2. **답변 대기** 세션을 최상단에 — 가장 높은 가치
3. **컨텍스트 사용량**과 경고 — 새 세션 시점 판단
4. 조회 전용. 세션을 조작하지 않는다

## 원칙

### 데이터는 기계를 떠나지 않는다

각자 자기 데이터만 본다. 중앙 서버·계정·외부 전송 없음.
백엔드는 `127.0.0.1` 에만 바인딩한다.

이유: 세션 기록에는 프롬프트 전문·절대 경로·브랜치명·PR 정보가 들어 있다.
남의 기계 데이터를 보관하면 유출 시 우리 책임이 된다.
개인 도구에서 그 책임을 질 이유가 없다.

### 조회 전용

세션 종료·재개 같은 조작을 넣지 않는다. 잘못 눌러 작업이 날아가는 위험 대비
얻는 편의가 작다.

### 읽기는 파일 끝에서부터

세션 기록이 크다 (실측: 총 327MB · 최대 21MB · 중앙값 2MB).
전체를 파싱하면 1,369ms 가 걸린다.
**역순으로 필요한 레코드까지만** 읽으면 86ms 다 — 15.9배.

수치는 계속 자라므로 [01-데이터](01-데이터.md) 의 재현 명령으로 다시 잴 것.

## 범위 밖 (명시)

- 세션 조작 (종료·재개·프롬프트 전송)
- **종료된 세션 목록** — 살아있는 세션만 다룬다 (#17). `claude agents --json` 이 주는
  목록이 곧 대상이고, 종료된 기록은 프로젝트별 개수(`sessionCount`)로만 센다.
  근거: 기록 파일 948개 중 **636개가 7일 이상** 된 것이라 위 목표 어디에도 걸리지 않고,
  전부 읽으면 수집이 198ms → 500ms 이상이 되어 [05-검증](05-검증.md) 2번의 목표를 깬다.
  **실측 후 의도한 생략이다** — 상세는 [01-데이터](01-데이터.md) "최종 상태 4종".
- 대화 내용 전문 표시 — 제목과 마지막 프롬프트 한 줄까지만
- 중앙 서버 · 계정 · 인증
- 다른 사람의 세션 조회
- 원격 기계 통합 — 1차 범위 밖. [04-배포](04-배포.md) 참고

## 결정된 사항

### 1. 브랜치 — `main` + `feature/*`

`dev`·`stg` 는 두지 않는다. 근거는 `CLAUDE.md` 참고.

### 2. 원격 저장소 — GitHub public

문서의 예제는 **모두 익명화**했다. 실제 프로젝트명·경로·발화는 들어가지 않는다.

### 3. 컨텍스트 표시 — 절대값 + 상한 + 퍼센티지

세션 기록의 모델명이 `claude-opus-5` 로만 남아 `[1m]` 변형이 구분되지 않는다
(실측: 671,229 토큰이 관측되었으나 기록상 모델명은 동일).
→ 설정의 기본 상한을 쓰되 **관측값이 넘으면 자동 상향**하고,
표시는 `절대값 / 상한 · %` 세 가지를 모두 낸다.

### 4. Claude 데스크탑 앱 — 대상 아님

조사 결과 데스크탑 앱의 `claude-code/`, `claude-code-vm/` 은 **번들된 CLI 바이너리**이고
세션 기록이 아니다. 대화는 서버(claude.ai)에 있고 로컬에는 IndexedDB 캐시뿐이라
읽어도 불완전하며 앱 업데이트마다 깨진다.

성격도 다르다 — Claude Code 세션은 "작업 중인 코드 프로젝트"이고
데스크탑 대화는 "질문"이다. 같은 보드에 섞으면 "답변 대기"의 의미가 흐려진다.

덧붙여, **데스크탑 앱에서 Claude Code 를 실행하면 그 세션은
`~/.claude/projects/` 에 동일하게 기록되어 이미 대상에 포함된다.**
포함되지 않는 것은 순수 대화뿐이다.
