# 03. 프론트

## 스택

| | 선택 | 이유 |
|---|---|---|
| 프레임워크 | **Vue 3 + Vite** | 화면이 하나라 규모가 맞다. 기존 React 스택에 더해 폭을 넓힌다 |
| 언어 | TypeScript | |

| 스타일 | **Tailwind v4** + SFC scoped | 전역 스킬의 스타일링 표준 (#16). 토큰은 `@theme` 으로 |

### 스타일 — Tailwind v4 (#16)

**`@tailwindcss/vite` 플러그인**으로 붙인다. PostCSS 를 거치지 않아
`postcss.config.js` 가 필요 없다 (Vite 를 쓰는 `qs-fe` 와 같은 방식 —
Next.js 쪽은 `@tailwindcss/postcss` 를 쓰지만 이 저장소엔 해당 없다).

v4 는 **CSS-first** 다 — `tailwind.config.js` 가 아니라 `@theme` 으로 토큰을 정의한다:

```css
/* src/styles.css */
@import "tailwindcss";

@theme {
  --color-panel: #161920;
  --color-state-waiting: #d9a441;   /* 앰버 — 시선을 끌어야 한다 */
  ...
}
```

여기 정의한 이름은 `bg-panel` 같은 유틸리티로도, `var(--color-panel)` 로도 쓸 수 있다.

#### ⚠️ 상태별 색은 유틸리티로 바꾸지 않는다

`.state-*` 는 **동적 생성**된다:

```vue
<div class="line" :class="`state-${session.state.toLowerCase()}`">
```

**Tailwind 는 문자열 조합으로 만든 클래스를 스캔하지 못해 빌드에서 잘라낸다.**
그래서 상태별 색은 `styles.css` 에 명시적 CSS 로 남겼다. 유틸리티로 옮기면 색이 사라진다.

#### ⚠️ 함께 유지해야 하는 것

```css
scrollbar-gutter: stable;              /* 빠뜨리면 #18 의 레이아웃 안정성이 되돌아간다 */
@media (prefers-reduced-motion: reduce)  /* 깜빡임 금지는 상시 표시 요구사항이다 */
```

shadcn-vue 는 **넣지 않는다.** 화면 1개짜리 조회 전용 도구라 컴포넌트 레이어가 과하다 —
버튼·모달·폼이 없다. 전역 스킬 실측으로도 shadcn 은 6곳 중 2곳뿐이다.

Composition API + `<script setup>` 을 쓴다.
빌드 결과는 `src/main/resources/static/` 으로 복사되어 Spring 이 서빙한다
([02-백엔드](02-백엔드.md) 참고).

FSD 는 적용하지 않는다 — 화면이 하나뿐이라 레이어가 오히려 부담이다.

### 파일 구조 (#11 구현 결과)

```
frontend/src/
├── lib/types.ts            # 백엔드 domain/ 레코드와 1:1. null 을 성실하게 표기한다
├── lib/format.ts           # 제목·브랜치·컨텍스트·경과시간·프롬프트 서식
├── lib/group.ts            # 상태 그룹핑과 정렬
├── lib/useBoardStream.ts   # SSE 구독
├── components/SessionLine.vue   # 세션 한 줄
├── components/ProjectRow.vue    # 프로젝트 한 건 (current + 접힌 others)
└── App.vue
```

**서식과 그룹핑을 순수 함수로 뺀 이유**: 컴포넌트 안에 인라인으로 두면
"제목 없는 세션이 렌더되는가"([05-검증](05-검증.md) 5번)를 렌더링 없이 검증할 수 없다.
다만 순수 함수 테스트만으로는 **헬퍼가 옳은데 템플릿이 그것을 안 부르는** 경우를
못 잡으므로, 컨텍스트 표시 같은 핵심은 **마운트한 DOM 텍스트**로도 확인한다.

**`types.ts` 에서 null 을 숨기지 않는다.** 역순 리더가 상한(512KB)에 걸리면
부분 결과를 반환하므로 `title`·`lastPrompt`·`branch` 가 실제로 비어서 온다
(실측: 세션 16개 중 제목 없는 것 5개, 브랜치 없는 것 1개).
낙관적으로 `string` 이라 적으면 렌더가 `undefined` 를 그대로 뿌린다.

### SSE 구독

서버는 `event: snapshot` 으로 보내므로 **`onmessage` 가 아니라
`addEventListener('snapshot', …)`** 을 쓴다 (`onmessage` 는 이름 없는 이벤트만 받는다).

```ts
const es = new EventSource('/api/stream')
es.addEventListener('snapshot', (e) => { board.value = JSON.parse(e.data) })
es.onerror = () => { /* 재연결은 브라우저가 자동 */ }
```

**중복 렌더는 서버 쪽에서 이미 막아뒀다** ([02-백엔드](02-백엔드.md)) —
과거 이벤트를 재생하지 않고 이벤트 id 도 쓰지 않으므로 브라우저가
`Last-Event-ID` 로 재생을 요구하지 않는다. 스냅샷은 누적이 아니라 매번 전체 상태라
같은 것을 두 번 받아도 같은 상태로 수렴한다. **클라이언트는 통째로 교체하면 된다.**

15초마다 오는 주석 프레임(`:`)은 끊김 감지용이고 이벤트가 아니라 무시된다.

**실측 (#11)** — 서버 응답이 문자 그대로 이렇게 온다:
```bash
$ curl -s -N http://127.0.0.1:7777/api/stream | head -c 60
event:snapshot
data:{"generatedAt":"2026-09-03T10:41:08.685813Z",...
```

재연결은 **브라우저에 맡긴다.** 직접 짜면 브라우저의 백오프와 겹쳐 연결이 두 개가 된다.
`onerror` 에서 `close()` 를 부르지 않는 것도 같은 이유다 — 부르면 자동 재연결까지 막힌다.

TanStack Query 는 쓰지 않는다. SSE 한 줄이면 되는데 캐시 계층이 불필요하다.

### 개발 중 API 연결

백엔드는 `127.0.0.1:7777` 에만 바인딩한다. Vite dev 서버는 포트가 다르므로
**프록시를 설정한다** — CORS 를 여는 것이 아니다
(여는 순간 "데이터는 기계를 떠나지 않는다"의 경계가 흐려진다).

```ts
// vite.config.ts
server: { proxy: { '/api': { target: 'http://127.0.0.1:7777', changeOrigin: false } } }
```

`localhost` 가 아니라 **주소를 그대로** 쓴다 — `localhost` 는 `::1` 로 풀릴 수 있고
백엔드는 IPv4 `127.0.0.1` 에 바인딩한다.

**실측 (#11)** — 양쪽 다 CORS 헤더가 0건이다:
```bash
$ curl -s -D - -o /dev/null -H "Origin: http://evil.example" \
    http://127.0.0.1:7777/api/sessions | grep -i access-control
(없음)

$ curl -s -D - -o /dev/null http://127.0.0.1:5173/api/sessions | grep -i access-control
(없음 — 프록시라 필요 없다)
```

### 한 줄에 담기는 것

```
프로젝트명   브랜치   제목
  경과시간 · ctx 토큰 · N번째 세션
  ↳ 마지막 프롬프트 (1줄, 넘치면 말줄임)
```

**마지막 프롬프트를 넣는 이유**: 제목만으로는 "내가 뭘 시켰더라"가 안 떠오른다.
마지막 발화를 보면 맥락이 즉시 복구된다.

### 정렬

```
답변 대기 → 멈춤 의심 → 작업 중 → 유휴
```
그룹 안 정렬은 **그룹마다 다르다** (#18 에서 분리).

| 그룹 | 정렬 | 왜 |
|---|---|---|
| 답변 대기 · 멈춤 의심 | **오래된 순** | 방치된 것이 위로 올라온다 — 이 도구의 가치가 여기 있다 |
| 작업 중 · 유휴 | **이름순** | 활동 시각이 5초마다 갱신되어 순서가 흔들린다 |

판정은 `group.ts` 의 `comparatorFor(state)` **한 곳을 통한다** —
호출부가 조건을 풀어 쓰면 상태를 추가할 때 그 호출부만 조용히 빠진다.

> **왜 나눴나 (#18)**: 처음엔 전 그룹을 오래된 순으로 뒀는데, 작업 중 세션은
> `lastActivityAt` 이 수집 주기마다 갱신되므로 "누가 더 오래됐는가"가 계속 뒤집혔다 —
> **내용이 하나도 안 바뀌었는데 줄이 위아래로 왕복했다.**
>
> ```
> 실측 — 레이아웃 샘플에서 y 좌표가 안 움직인 비율
>   고치기 전  264회 중 27%
>   고친 후     27회 중 81%
> ```
> 남은 19% 는 전부 `textLen` 이 함께 변한 실제 내용 변화이고,
> **`scrollH`·`textLen` 이 동일한데 y 만 움직인 경우(진짜 튐)는 0건**이다.
>
> 유휴도 이름순인 이유: 2시간 이상 조용한 것들 사이의 선후는 의미가 없고,
> 활동이 생기면 작업 중으로 빠지므로 여기서도 시각은 흔들리는 키다.

**종료된 세션은 다루지 않는다** (#17) — 상태가 4종뿐이고 토글도 없다.
백엔드가 pid 없는 항목을 걸러내므로 화면에 오는 것은 살아있는 세션뿐이다.
근거는 [00-개요](00-개요.md) "범위 밖".

## 시각 규칙

상태를 **색이 아니라 위치와 라벨로** 먼저 구분한다. 색은 보조.

| 상태 | 색 |
|---|---|
| 답변 대기 | 앰버 — 시선을 끌어야 함 |
| 멈춤 의심 | 레드 |
| 작업 중 | 그린 |
| 유휴 | 회색 |

종료 상태는 없다 (#17).

컨텍스트 토큰은 **절대값 · 상한 · % 셋을 모두** 낸다
([00-개요](00-개요.md) 결정사항 3). 기록의 모델명이 `claude-opus-5` 로만 남아
`[1m]` 변형이 구분되지 않아 **분모가 틀릴 수 있다** — 그래도 절대값으로는 판단이 된다.
API 가 `contextTokens` · `contextLimit` · `contextRatio` 를 모두 준다.

| 층 | 도구 | 무엇을 본다 |

### e2e 는 백엔드를 띄우지 않는다

CI 러너에는 `~/.claude/projects/` 도 `claude` CLI 도 없어 백엔드를 띄워도
빈 스냅샷밖에 못 준다. 검증 대상은 "서버가 도는가"가 아니라
**"이 응답이 오면 화면이 이렇게 된다"** 이므로 `EventSource` 를 가짜로 바꿔 주입한다.
세션 0개·제목 없음·긴 브랜치명 같은 경계를 **결정적으로** 재현하려면 이쪽이어야 한다.

`page.route` 로는 안 된다 — `route.fulfill` 은 응답을 **한 번에** 주므로
스트림을 열어둔 채 몇 초 뒤 다음 이벤트를 밀어넣을 수 없다.
재연결·중복 렌더를 검증하려면 그 제어가 필요하다.

⚠️ 가짜 `EventSource` 는 **`onmessage` 를 실제 브라우저와 똑같이** 다뤄야 한다 —
이름 붙은 이벤트를 `onmessage` 로도 흘리면, 구현이 `onmessage` 로 짜여 있어도
테스트가 통과해 **잡으려던 것을 정확히 못 잡는다.**

**실제 데이터 확인은 따로 한다.** 주입한 응답으로는 "실제로 오는 값"을 못 본다 —
백엔드를 띄우고 브라우저를 붙여 눈으로 대조한다([05-검증](05-검증.md) 5번).

### eslint — 줄바꿈 취향 규칙 3개는 껐다

`vue/max-attributes-per-line`·`vue/singleline-html-element-content-newline`·
`vue/html-self-closing`. Prettier 를 두지 않은 상태에서 `--max-warnings 0` 과 겹치면
**CI 가 취향으로 빨개진다** — 실측으로 32건이 떴고 전부 줄바꿈 위치였다.

나머지 vue 권장 규칙은 그대로 둔다. `no-console`·`no-debugger` 는 `error` 다
(전역 `security.md`).

## 상시 표시를 고려한 처리

Studio Display 한쪽에 띄워둘 가능성이 있다. 그 경우:

- 배경은 어둡게, 전체 휘도를 낮게
- 갱신 시 레이아웃이 튀지 않게 (높이 고정, 내용만 교체)
- 깜빡이는 애니메이션 금지

**실측 (#15, 140분)**: 가로 오버플로 0회, 콘솔 에러 0건.
두 번째 항목은 처음엔 미달이었고(y 가 안 움직인 샘플 27%) **#18 에서 고쳤다** — 위 "정렬" 참고.

⚠️ **`shifted=N` 이라는 숫자만으로는 원인을 못 찾는다.** 줄마다 이름을 붙여 봐야
"작업 중 그룹이 서로 자리를 맞바꾼다"가 보였다([tools/observe/jitter.mjs](../tools/observe/jitter.mjs)).
그리고 **"y 가 움직였다"를 곧 "튀었다"로 읽지 않는다** — 세션이 실제로 늘거나 줄면
움직이는 게 맞다. `scrollH`·`textLen` 이 **동일한데** y 만 바뀐 것을 세야 한다.

OLED 에 띄울 계획이면 정지 화면이 되지 않도록 추가 검토가 필요하다.
1차 범위 밖.
