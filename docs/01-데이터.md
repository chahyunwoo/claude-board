## 소스 B — 세션 기록

```
~/.claude/projects/{경로를-하이픈으로-치환}/{sessionId}.jsonl
```

경로 인코딩 예:
```
/Users/me/projects/notify-service
```

`sessionId` 로 파일을 직접 찾을 수 있으므로 **인코딩 규칙에 의존하지 말고
`~/.claude/projects/*/{sessionId}.jsonl` 글롭으로 찾는다.** (규칙이 바뀌어도 안전)

### `lastPrompt` — `last-prompt` 레코드를 믿지 말 것

이름 때문에 `last-prompt` 레코드에서 얻을 것 같지만 **거기엔 발화 텍스트가 없다.**

```json
{"type":"last-prompt","leafUuid":"c1f0d587-...","sessionId":"048592ac-..."}
```

`leafUuid` 만 있고, 그 uuid 가 가리키는 레코드는 **user 가 아닌 경우가 많다**
(실측한 한 파일에서는 assistant 13개 / attachment 19개를 가리켰다).

**실측**: `last-prompt` 가 있는 파일 24개 중 **user 레코드를 가리킨 것은 16개**뿐.

재현:
```bash
tot=0; hit=0
for f in $(ls -S ~/.claude/projects/*/*.jsonl | head -25); do
  n=$(jq -r 'select(.type=="last-prompt").leafUuid' "$f" 2>/dev/null | wc -l | tr -d ' ')
  [ "$n" = "0" ] && continue
  tot=$((tot+1))
  jq -r 'select(.type=="last-prompt").leafUuid' "$f" | sort -u > /tmp/l.txt
  u=$(jq -r 'select(.type=="user" and .uuid) | .uuid' "$f" | grep -cFf /tmp/l.txt || true)
  [ "$u" -gt 0 ] && hit=$((hit+1))
done
echo "last-prompt 있는 파일: $tot / 그중 user 를 가리킨 파일: $hit"   # → 24 / 16
```

→ **역순 스캔으로 `tool_result` 가 아닌 마지막 `user` 레코드에서 얻는다.**
`content` 가 문자열인 경우와 배열인 경우가 모두 존재하므로 둘 다 처리할 것.

### 컨텍스트 사용량

`assistant` 레코드의 `message.usage` 에서 **가장 마지막 값**을 쓴다.

```json
{
  "input_tokens": 2,
  "cache_creation_input_tokens": 728,
  "cache_read_input_tokens": 454492,
  "output_tokens": 2792
}
```

```
컨텍스트 ≈ input_tokens + cache_read_input_tokens + cache_creation_input_tokens
         = 2 + 454492 + 728 = 455,222
```

실측: `notify-service` 세션이 458,014 토큰이었다.
`output_tokens` 는 합산하지 않는다 (다음 요청의 입력이 되긴 하나 이미 cache_read 에 반영됨).

## 상태 판별 규칙 — 이 도구의 핵심

세션 파일을 **끝에서부터 역순으로** 읽어 첫 `user` 또는 `assistant` 레코드를 찾는다.

**레코드 타입만으로는 판별되지 않는다. `message.content` 의 블록까지 봐야 한다.**

```
assistant 인데 content 에 tool_use 블록      → 작업 중 (도구 결과를 기다림)
assistant 이고 tool_use 아님 (text 로 끝남)  → 답변 대기
user 인데 content 에 tool_result 블록        → 작업 중 (도구 결과 반환)
user 이고 tool_result 아님                   → 작업 중 (사용자 입력 직후)
```

즉 `user` 와 `assistant` **양쪽 모두** 두 갈래로 갈린다. 함정이 대칭이다.

### 함정 ① 도구 결과는 `type: "user"` 로 기록된다

이걸 사용자 입력으로 오인하면 "작업 중"과 "답변 대기"가 뒤바뀐다.

### 함정 ② `assistant` 라고 다 답변 완료가 아니다

`tool_use` 로 끝난 `assistant` 는 **도구를 호출하고 결과를 기다리는 중**이다.
사용자를 기다리는 게 아니므로 답변 대기가 아니다.

**실측 (2026-09-03)** — 살아있는 세션 13개의 마지막 대화 레코드:

```
NAME                         TYPE       BLOCKS
for-projects-d0              assistant  text
chahyunwoo-6b                assistant  text
cgv-ticketing-macro-f0       assistant  text
cgv-ticketing-macro-c0       user       tool_result
discord-bot-5a               assistant  text
cafe24-playbook-f5           assistant  text
concert-ticketing-macro-d1   assistant  text
concert-ticketing-macro-c4   assistant  text
imax-watch                   assistant  text
discord-bot-8a               user       tool_result
discord-bot-cc               assistant  text
bubble-house-5c              assistant  tool_use   ← 실제로 작업 중
claude-board-e5              assistant  tool_use   ← 실제로 작업 중
```

이 구분이 없으면 아래 2개가 "답변 대기"로 **오보**된다:

```
구분 없음: {"waiting":12, "working":0}   ← 작업 중 세션이 0개
구분 있음: {"waiting":10, "working":2}   ← 실제와 일치
```

재현:
```bash
claude agents --json | jq -r '.[] | "\(.sessionId)\t\(.name)"' | while IFS=$'\t' read -r sid name; do
  f=$(ls ~/.claude/projects/*/$sid.jsonl 2>/dev/null | head -1)
  [ -z "$f" ] && continue
  res=$(jq -c 'select(.type=="user" or .type=="assistant") |
    {t:.type, b:(if (.message.content|type)=="array"
      then ([.message.content[].type]|unique|join(",")) else "string" end)}' "$f" | tail -1)
  printf "%-28s %s\n" "$name" "$res"
done
```

### 판별 코드

```python
def block_types(rec):
    content = (rec.get('message') or {}).get('content')
    if not isinstance(content, list):
        return set()
    return {b.get('type') for b in content if isinstance(b, dict)}

blocks = block_types(rec)
if rec['type'] == 'assistant':
    kind = 'assistant_tool_use' if 'tool_use' in blocks else 'assistant'
else:
    kind = 'tool_result' if 'tool_result' in blocks else 'user'
```

구현은 `collect/TranscriptReader.java` 의 `absorbAssistant`·`absorbUser`,
판정은 `collect/StateResolver.java` 의 `isInProgress` 를 볼 것.

### 최종 상태 5종

| 상태 | 조건 | 정렬 |
|---|---|---|
| `waiting` 답변 대기 | 마지막 = assistant(text) · pid 있음 | 1 |
| `stalled` 멈춤 의심 | 마지막 = 진행 중인데 임계 초과 | 2 |
| `working` 작업 중 | 마지막 = 진행 중 · 최근 갱신, 또는 user 입력 직후 | 3 |
| `idle` 유휴 | pid 있음 · 오래 조용함 | 4 |
| `ended` 종료 | pid 없음 (기록만 존재) | 기본 숨김 |

**"진행 중"은 두 형태다** — `tool_result`(도구 결과가 돌아옴)와
`assistant + tool_use`(도구 호출 후 결과 대기). 둘 다 다음 턴을 기다리는 상태라
오래 조용하면 멈춤 의심이 된다. 판정은 `StateResolver.isInProgress` 한 곳을 통한다.

`waiting` 은 오래 조용해도 `idle` 로 내려가지 않는다 —
기다리는 중인 것은 시간이 지나도 변하지 않고, 이 도구의 최고 가치 상태다.

임계값 (2026-09-03 기준, 조정 여지 있음):
```
stalled : 마지막 활동 > 10분 이고 진행 중 상태
idle    : 마지막 활동 > 2시간 (waiting 제외)
```

## 프로젝트 단위 집계

세션이 아니라 **프로젝트가 1급 단위**다. (한 프로젝트에 세션이 계속 이어짐)

```
프로젝트 키 = cwd
  현재 세션   = 그 프로젝트의 살아있는 세션 중 mtime 최신
  이전 세션들 = 나머지 (접어서 표시)
  세션 순번   = 그 프로젝트 기록 파일을 시각순 정렬했을 때의 index
```

`web-client` 처럼 한 프로젝트에 세션이 여러 개 동시에 살아있을 수 있다.
그 경우 **가장 최근 것을 현재로** 삼고 나머지는 접는다.

## 성능

**실측 (2026-09-03)** — 데이터가 초안 작성 시점보다 훨씬 커졌다:

```
파일 109개 · 총 327MB · 최대 21MB · 중앙값 2MB · 1MB 초과 84개
```

⚠️ 이 수치는 **재는 순간마다 달라진다.** 위 값을 잰 직후 다시 쟀더니
110개 / 328MB / 1MB 초과 85개였다 — 세션이 도는 동안에도 기록이 계속 append 되기 때문이다.
**절대값을 문서에서 읽지 말고 아래 명령으로 직접 재라.**

재현:
```bash
ls ~/.claude/projects/*/*.jsonl | wc -l          # 109
du -ch ~/.claude/projects/*/*.jsonl | tail -1    # 327M
du -k  ~/.claude/projects/*/*.jsonl | awk '$1>1024' | wc -l   # 84
```

⚠️ 초안에 적혀 있던 "최대 5.8MB" 는 이제 틀렸다. 세션 기록은 계속 자라므로
이 수치는 **읽을 때마다 다시 재는 것**이 맞다. 위 명령이 그 수단이다.

- 전체 파싱 금지. 끝에서 역순으로 읽되 필요한 필드를 다 채우면 즉시 중단
- `aiTitle`·`lastPrompt` 는 파일 뒤쪽에 있을 가능성이 높다 (갱신될 때마다 append)
- 역순 리더 실측: **86ms** vs 전체 파싱 1,369ms = **15.9배**
- 전체 갱신은 285ms 로 목표(200ms) 미달. 병목은 `claude agents --json`
  서브프로세스(~200ms, Node CLI 부팅)로 **이 저장소 밖에 있다** —
  `@Scheduled` 캐시로 해소한다. [02-백엔드](02-백엔드.md) 참고
