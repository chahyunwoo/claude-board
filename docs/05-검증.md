# 05. 검증

작업협약 3번: **"다 된 것 같다"로 끝내지 않는다.**
아래는 각 단계에서 실제로 돌려서 pass/fail 이 나오는 수단이다.

## 1. 상태 판별이 실제와 맞는가 — 가장 중요

이 도구의 가치 전부가 여기 걸려 있다.

```bash
java -jar build/libs/claude-board.jar --json | jq -r '.projects[] |
  "\(.current.state)\t\(.name)\t\(.current.title // "-")"'
```

**눈으로 대조한다.** 각 세션의 Cursor 창을 열어 실제로 답변 대기 상태인지 확인.

합격 기준: 살아있는 세션 전부에 대해 판별이 일치.
불일치가 하나라도 있으면 `collect/StateResolver.java` 를 고친다.

### 반드시 넣을 단위 테스트

```
① 마지막이 assistant                     → waiting
② 마지막이 user + tool_result 블록 포함  → working   ← 이걸 빠뜨리면 상태가 뒤집힌다
③ 마지막이 user + 순수 텍스트            → working
④ 파일이 비어 있음                       → 예외 없이 부분 결과 반환
⑤ 마지막 줄이 깨진 JSON                  → 그 줄만 건너뛰고 계속
```

②가 핵심이다. 도구 결과가 `type: "user"` 로 기록되므로
순진하게 짜면 "작업 중"과 "답변 대기"가 정확히 반대로 나온다.

### 되돌리기 검증

②의 판별 로직을 일부러 제거하고 테스트가 **빨개지는지** 확인한다.
통과만 보고 넘어가지 않는다.

## 2. 성능

```bash

```

(실측 171ms — 역순 리더와 차이가 없어 보인다). **JSON 파싱까지 해야 공정하다.**

```bash

```

### 전체 갱신이 200ms 를 넘으면 어디가 병목인지 나눠 재라

`--json` 전체는 285ms 로 목표를 넘는다. 구간을 나눠 보면:

```bash

201ms 202ms 207ms 204ms 199ms
```

**~200ms 가 `claude agents --json` 서브프로세스**(Node CLI 부팅)로 저장소 밖이다.
리더를 더 조여도 소용없고, `@Scheduled` 캐시로 푼다.
→ "느리다"를 봤으면 **어느 구간인지 먼저 재라.** 엉뚱한 곳을 최적화하게 된다.

### SSE emitter 정리

누수는 예외를 내지 않고 조용히 쌓인다. 붙였다 끊고 **실제로 걷히는지** 본다.

```bash
# 연결 5개를 붙여둔 상태에서
jcmd <pid> GC.class_histogram | grep -iE "SseEmitter|StreamController"
# 모두 끊고 하트비트 주기(기본 15초)를 기다린 뒤 다시
```

⚠️ **"0" 만 보고 통과시키지 말 것.** 0 이 "정리됐다"인지 "측정이 안 된다"인지
구별되지 않는다. **연결 중일 때 실제로 세어지는지를 먼저 보인 뒤** 0 을 근거로 쓴다.

실측 (#5): 연결 5개일 때 `SseEmitter` 5개가 세어졌고, 끊은 뒤 0 이 됐다.
`lsof -nP -iTCP:7777 | grep -c ESTABLISHED` 도 0.

#### ⚠️ 이 함정은 실제로 재발한다 — 계측 시점이 어긋나는 형태로

**실측 (#11)**: 브라우저 3개를 붙이고 셌는데 **"연결 3개일 때"가 0** 으로 나왔다.
누수가 없어서가 아니라 **브라우저가 이미 닫힌 뒤에 셌기** 때문이다 —
계측을 셸에서 `sleep` 으로 맞추려다 타이밍이 어긋났다.
그대로 통과시켰으면 "정리됐다"와 "측정이 안 된다"를 구별하지 못한 채 넘어갔을 것이다.

→ **브라우저를 띄운 것과 같은 프로세스 안에서 센다.** 그러면 살아있는 것이 보장된다.

```
연결 전:        0
연결 3개일 때:  12     ← 실제로 세어진다 (브라우저는 페이지당 여러 소켓을 쓴다)
끊은 직후:      0
하트비트 후:    0
```

숫자가 3 이 아니라 **12** 인 것도 정보다 — 브라우저 연결 수와 소켓 수는 다르다.
"3개 붙였으니 3이어야 한다"고 기대했다면 이번엔 그 기대가 틀렸다.

## 5.5 시간에 걸친 관찰 — 한 시점 검증으로는 안 보이는 것

위 1~5번은 전부 **한 시점**을 본다. 그것으로는 안 보이는 것이 있다.
도구와 사용법은 [tools/observe/](../tools/observe/README.md) 에 있다.

**실측 (2026-09-03, #15, 126분 가동)**:

```bash
(cd frontend && npm run build) && ./gradlew bootJar
java -jar build/libs/claude-board.jar &   # PID 를 기억한다
tools/observe/sample.sh $PID &            # 1분마다 상태·자원
node tools/observe/browser-watch.mjs /tmp/observe 300 &   # 브라우저 계측
```

### ⭐ 상태 전이는 임계 시점을 실제로 지나야 확인된다

`WORKING → STALLED` 가 `stalled-after`(10분)에 일어나는지는 **단위 테스트로는
"그 시각을 주면 그 답이 나온다"까지만** 검증된다. 실제로 시간이 흘러야 확인된다.

```
21:52:35  WORKING  quietSec=543  ( 9분 03초)   ← 임계 미만
21:53:36  STALLED  quietSec=604  (10분 04초)   ← 전이 발생
21:55:36  WORKING  quietSec=8                  ← 활동 재개, 즉시 복귀
```

STALLED 관측 136건 중 **최소 `quietSec` 이 604** 였다 — 임계가 새는 곳이 없다.

### ⭐ SSE 30분 만료 후 재연결

`StreamController.TIMEOUT_MS` 가 30분이다. 그 뒤 재연결이 되는지는
**30분을 넘겨야** 보인다. `EventSource` 를 감싸 `opens` 를 센다:

```
opens=1 errors=0 snapshots=342   (20:49)
opens=2 errors=1 snapshots=349   (20:50)   ← 만료 → 자동 재연결
```
126분 동안 4번 연결됐다(30분 주기). `snapshots` 가 끊김 없이 증가하고 중복 렌더도 없다.

⚠️ **프레임 개수만 보고 "안 끊겼다"고 읽지 말 것** — 실측으로 밟았다.
`curl` 은 자동 재연결을 안 하므로 **마지막 프레임의 시각**을 봐야 한다.

### ⭐ 메모리는 "늘어나는가"를 구간 평균으로 본다

한 시점의 RSS 는 GC 타이밍에 따라 크게 흔들려 판단 근거가 못 된다.

```
30분 단위 평균 RSS
  20:00~  422MB      ← JVM 힙 워밍업
  21:00~  186MB
  22:00~  193MB      ← 수렴. 누수면 여기가 커진다
스레드 53 → 54,  fd 34 → 36     (연결이 붙었다 끊겨도 안 늘어난다)
```

### ⭐ 레이아웃 튐은 "줄 수가 같은데 y 가 바뀌는가"로 본다

갱신 때 세션이 실제로 늘거나 줄면 y 가 움직이는 게 정상이다.
**줄 수·높이·상태가 모두 같은데 y 만 바뀌면** 그것이 진짜 튐이다.

```bash
node tools/observe/jitter.mjs    # 줄마다 이름을 붙여 y 변화를 낸다
```

실측 (#15) — 레이아웃 샘플 264회 중 y 가 안 움직인 것이 **27%뿐**이었고,
원인은 `group.ts` 의 정렬 키였다. **#18 에서 고쳐 81% 가 됐다.**

`shifted=N` 이라는 숫자만으로는 **어느 줄이 왜** 움직였는지 몰라 원인을 못 찾는다.

### ⚠️ "y 가 움직였다"를 곧 "튀었다"로 읽지 말 것

세션이 실제로 늘거나 줄면 y 가 움직이는 게 **맞다.** 판정식은 이렇다:

```bash
# scrollH·textLen 이 동일한데 y 만 바뀐 것 = 진짜 튐
awk -F'\t' 'NR>1 { if (pH!="" && $4>0 && pH==$2 && pT==$5) print $1" 진짜 튐 shifted="$4; pH=$2; pT=$5 }' layout.tsv
```

**실측 (#18 수정 후)**: `shifted>0` 이 5건 남았지만 **전부 `textLen` 이 함께 변한**
실제 내용 변화였고, 위 판정식에 걸리는 것은 **0건**이었다.
"81% 밖에 안 된다"고 읽었다면 그 판단은 틀렸을 것이다.

### ⭐⭐ "가드가 있다"와 "가드가 불린다"는 다르다

**실측 (#17)**: `grep ENDED` 로는 코드가 있어 보였지만 **호출 경로가 없었다** —
`Aggregator` 가 살아있는 세션만 순회하므로 `if (!alive)` 분기에 절대 안 걸렸고,
프론트의 `ended` 토글은 **항상 아무것도 하지 않았다.**

더 나쁜 것은 **그 토글을 검사하는 e2e 테스트가 통과하고 있었다**는 점이다 —
`ENDED` 가 든 스냅샷을 **직접 주입**해서 프론트 필터링만 검사했기 때문이다.
프론트는 옳았고 **데이터 공급원이 끊겨** 있었다.

토글·분기를 만들었으면 **실전에서 그 경로에 도달하는 입력이 존재하는지** 센다:

```bash
claude agents --json | jq '[.[].pid] | {total: length, nonpositive: (map(select(. <= 0)) | length)}'
# → nonpositive 가 0 이면 그 분기는 도달 불가능하다
```

⚠️ **주입식 테스트는 "이 값이 오면 이렇게 된다"까지만 증명한다.**
"그 값이 실제로 오는가"는 **공급원 쪽에서** 따로 검사해야 한다
(#17 은 `AggregatorTest` 에 넣었다 — 가짜 agents JSON 을 실제 파싱 경로에 태운다).

→ **#17 에서 `ENDED` 를 걷어냈다.** 상태는 4종이고, pid 없는 항목은
`Aggregator` 가 순회에서 걸러내며 `errors` 로 알린다.

## 5.7 스타일 전환 — 화면이 같은지 어떻게 아는가

`@theme` 으로 토큰을 옮기거나 CSS 를 손대면 **DOM 텍스트는 그대로인데 화면이 깨진다.**
`npm run test:e2e` 가 초록이어도 못 잡는다.

### ⭐⭐ 라이브 백엔드로 전후를 비교하지 말 것

**실측 (#16)**: 전환 전 `scrollH=1562`, 전환 후 `1540` 이 나와 *"22px 깨졌다"* 고 판단하고
원인을 찾느라 시간을 썼다. 그런데 **기준선 번들로 되돌려 다시 재도 1540** 이었다 —
그 사이 **세션 데이터가 바뀐 것**이었다(`textLen` 2573 → 2541).

세션은 5초마다 갱신되므로 **라이브 데이터로는 스타일 차이와 데이터 변화가 구별되지 않는다.**

→ **고정 스냅샷을 주입해서 잰다.** e2e 처럼 `EventSource` 를 가짜로 바꾸면
데이터가 고정되어 스타일 차이만 순수하게 드러난다.

```
전환 전:  scrollH=900 lines=3 projects=3 overflow=false
전환 후:  scrollH=900 lines=3 projects=3 overflow=false
diff → 차이 없음
```

크기뿐 아니라 **색·테두리·radius·패딩·폰트**까지 `getComputedStyle` 로 받아 대조한다.

### ⭐ 그 비교가 실제로 차이를 잡는지 먼저 보인다

"차이 없음"이 *"정말 같다"* 인지 *"검사가 무력하다"* 인지 구별되지 않는다
(4번 SSE emitter 의 "0" 함정과 같은 형태다).

**실측 (#16)**: 토큰 색 하나를 마젠타로 바꿔 검사가 잡는지 먼저 확인했다:

```
< "color": "rgb(217, 164, 65)"
> "color": "rgb(255, 0, 255)"
```

잡혔으므로 그 뒤의 "차이 없음"을 근거로 쓸 수 있다.

### ⚠️ CSS 변수 이름을 바꾸면 컴포넌트가 조용히 깨진다

`@theme` 은 `--color-` 접두사를 요구한다. `--panel` → `--color-panel` 로 옮기면
**기존 `var(--panel)` 이 전부 해석되지 않아** 배경·테두리가 사라진다.
예외가 나지 않고 **조용히** 깨지므로 눈으로 봐야 안다.

```bash
# 옛 이름이 남았는지 센다 (--state-color 는 .state-* 가 설정하는 로컬 변수라 정상)
grep -ohE 'var\(--[a-z-]+' frontend/src/App.vue frontend/src/components/*.vue | sort -u
```
