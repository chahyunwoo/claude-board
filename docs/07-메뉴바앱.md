# 07 · 메뉴바 앱 (macOS)

브라우저 탭을 열어두지 않고 메뉴바에서 본다. `macos/` 아래에 있고
백엔드(`127.0.0.1:7777`)를 SSE 로 구독한다.

- 소스: `macos/Sources/ClaudeBoardMenu/` (App · BoardClient · Models)
- 빌드·설치: `macos/build-app.sh install` → `/Applications/Claude Board.app`
- 이슈 #37 · PR #38

## 무엇을 하나

- 메뉴바에 답변 대기 수(`● 8`). **0 이면 숫자를 안 낸다** — 기다리는 게 없으면 조용해야 한다
- 눌러서 상태별 목록 (답변 대기 → 멈춤 의심 → 작업 중 → 유휴)
- **세션 하나 = 한 줄.** 같은 폴더의 세션도 각자 줄을 가진다
- 행을 누르면 그 자리에서 펼쳐진다 — PID·모델·권한·브랜치·시작·마지막 활동·컨텍스트·경로
- 체크박스로 여러 개 골라 **kill 명령을 클립보드에 복사**
- 백엔드가 죽으면 되살린다 (최대 5회 / 10분 창)

## 시각

**이모지를 쓰지 않는다.** `⏳⚠▶·` 로 시작했다가 전부 SF Symbol 로 걷어냈다 —
컬러 이모지는 폰트마다 렌더링이 다르고, 메뉴바의 다른 아이템(전부 단색 심볼)과
섞이지 않아 혼자 튄다. SF Symbol 은 텍스트 색·굵기를 따라가고 다크모드에서도 맞춰진다.

⚠️ **SF Symbol 이름이 틀리면 컴파일은 통과하고 화면만 빈 칸이 된다.**
조용히 실패하므로 이름을 바꿨으면 반드시 실행해서 확인한다:

```swift
NSImage(systemSymbolName: "circle.dotted", accessibilityDescription: nil) != nil
```

색은 `SessionState.rgb`(Models.swift) **한 곳에서만** 정한다. 웹 화면
([03-프론트](03-프론트.md) "시각 규칙")의 앰버·레드·그린·회색을 따르되 **채도를 낮춘다** —
그 문서가 *"색이 아니라 위치와 라벨로 먼저 구분한다, 색은 보조"* 라고 정했는데
웹 값을 그대로 가져왔더니 색이 먼저 튀어 원칙을 어기고 있었다.
**라벨 글씨에는 색을 넣지 않는다.** 아이콘에만 남긴다.

⚠️ **단 컨텍스트 85% 만은 채도를 낮추지 않는다.** 한 번 낮췄다가 되돌렸다 —
옆의 앰버(70%)와 구별이 안 됐다. 나머지를 조용하게 만든 이유가 이 하나를 튀게
하기 위해서인데 여기서 채도를 낮추면 앞뒤가 안 맞는다. 굵게 + 칩 배경까지 붙인다.

**클릭 타겟은 아이콘 크기와 다르다.** 체크박스 아이콘은 16pt 지만 클릭 영역은
`frame`+`contentShape` 로 28pt 를 준다(macOS 권장). 아이콘만 키우면 손이 정확해야 눌린다.

## 조회 전용 원칙을 지키는 방식

**앱이 세션을 죽이지 않는다** ([00-개요](00-개요.md) "조회 전용", 범위 밖 명시).
kill 명령을 클립보드에 넣어줄 뿐이고, 실제로 죽는 것은 터미널에서 붙여넣고
엔터를 칠 때다 — 그 사이에 눈으로 확인하는 단계가 있어
*"잘못 눌러 작업이 날아가는"* 경로가 아니다.

복사할 명령을 화면에 **먼저 보여주는 것**도 같은 이유다.
보이지 않는 것을 클립보드에 넣지 않는다.

`kill -9` 가 아니라 SIGTERM 을 쓴다. Claude Code 가 기록을 정리할 기회를 준다.

## 밟은 것 — 다시 밟지 말 것

### 1. `maxHeight` 만으로는 목록이 눌린다

`VStack` 안의 `ScrollView` 는 남는 공간을 배분받지 못하면 **최소 높이로 쪼그라든다.**
상한이 420 이어도 실제로는 한두 줄만 그려졌다. `minHeight` 를 함께 줘야 한다.

⚠️ **오진 경로**: 처음엔 "창이 안 열린다"고 보고 `MenuBarExtra` 배선과
`Group`/`Label` 이름 충돌을 의심했다 — 둘 다 헛다리였다.
심어둔 진단 로그가 `groups=2` 를 찍고 있었던 것이 곧 **"창은 열렸다"** 는 증거였는데,
전제를 의심하지 않아 못 읽었다. **로그가 이미 답을 말하고 있는지 먼저 볼 것.**

### 2. 선택은 pid 가 아니라 sessionId 로 잡는다

pid 는 프로세스가 죽으면 OS 가 재사용한다. 선택해둔 사이에 그 세션이 끝나고
pid 가 다른 프로세스로 넘어가면 **엉뚱한 것을 죽이는 명령**이 만들어진다.
pid 는 명령을 만드는 순간 최신 스냅샷에서 다시 읽는다.

    [정상]            kill 100 200 300  stale=0
    [b종료+pid재사용]  kill 100 300      stale=1   ← 200 이 빠진다
    [전부종료]         nil               stale=3

사라진 선택은 조용히 빼지 않고 개수를 표시한다.

### 3. `ISO8601DateFormatter` 기본값은 백엔드 형식을 못 읽는다

백엔드는 밀리초를 붙여 보낸다(`.230Z`). `withFractionalSeconds` 없이는
파싱이 `nil` 이 되어 "시작"·"마지막 활동" 줄이 **조용히 사라진다.**
되돌려서 확인했다:

    제거 시  2026-09-04T02:53:56.230Z -> nil      ← 백엔드 실제 형식이 죽는다
            2026-09-04T02:53:56Z     -> 4분 전    ← 밀리초 없는 것만 산다
    복구 후  2026-09-04T02:53:56.230Z -> 4분 전

### 4. 프로젝트당 한 줄이면 세션이 숨는다 — 세션 하나 = 한 줄

같은 폴더에서 Claude 를 여러 번 띄우면 API 는 `current` 하나와 `others[]` 로 준다.
화면을 **프로젝트당 한 줄**로 그리면 `others` 가 통째로 사라진다.

> **실측**: `cgv-ticketing-macro` 의 current 가 54.4%, others 에 61.6% 가 있었는데
> 화면에는 54.4% 만 떴다. **더 위험한 쪽이 보이지 않았다.**

⚠️ **두 번에 걸쳐 틀렸다.** 처음엔 `others` 를 **펼침 영역 안에만** 넣었다.
그것으로는 부족하다 — 폴더를 하나씩 펼쳐봐야 진짜 최댓값을 안다면
*"훑어보다 위험을 발견한다"* 는 경고의 목적이 성립하지 않는다.
다음엔 **프로젝트 최댓값**을 대신 내고 `↑` 를 붙였는데, 사용자가 그 기호를
이해하지 못했다 — **설명이 필요한 UI 는 잘못된 UI 다.**

정답은 단순했다: **세션이 둘이면 줄도 둘이다.**
실측으로 다 펴도 11줄 → 12줄이라 길어지지도 않았다.

부수 효과로 **상태 분류도 정확해졌다.** 전에는 프로젝트 단위로 묶여
`others` 의 세션이 `current` 의 상태에 끌려갔다. 지금은 각자 자기 그룹으로 간다.

```
같은 폴더 cgv:  A(답변대기) → 답변 대기 그룹
               B(작업중)   → 작업 중 그룹    ← 전에는 둘 다 답변 대기였다
```

같은 폴더의 줄이 여럿이면 `#0` `#4` 처럼 `ordinal` 을 붙여 구분한다.

### 5. launchd 는 고장나지 않았다 — 앞선 진단이 틀렸다

⚠️ **정정 (2026-09-04).** 이 문서와 `local.claude-board.plist` 주석은
*"이 기계의 launchd 는 KeepAlive 가 동작하지 않는다"* 고 적고 있었다. **틀렸다.**
같은 기계에서 `KeepAlive: true` 를 쓰는 에이전트가 둘 다 정상 동작한다:

    $ launchctl list | grep -E 'caddy|concert'
    2479  0  homebrew.mxcl.caddy          ← KeepAlive:true, 실행 중
    -     0  com.chahyunwoo.concert-watch ← KeepAlive:true

진짜 원인은 **종료 코드 143** 이다.

    $ launchctl list | grep local.claude-board
    -  143  local.claude-board

`143 = 128 + 15` = SIGTERM. `KeepAlive: true` 는 *무조건* 재시작이 아니라,
launchd 가 **"정상 종료"로 판단하면 되살리지 않는다.** `kill`(SIGTERM)로 죽여보는
테스트는 정확히 그 조건을 만든다 — **테스트 방법이 "안 살아나는 조건"을 만들고 있었고,
그것을 launchd 고장으로 읽었다.**

되살리기를 원한다면 `SuccessfulExit` 를 명시하거나, 애초에 SIGTERM 이 아닌 방식으로
검증해야 한다. 지금 구조(앱이 워치독을 겸함)는 그것대로 동작하므로 유지하되,
**"launchd 가 고장났다"를 근거로 삼지 말 것.**

로그인 항목(시스템 설정 > 일반 > 로그인 항목)은 부팅 시 앱을 띄우는 별개 수단이고,
`build-app.sh install` 이 `osascript` 로 등록한다. 이건 그대로 유효하다.

## 검증

CI 는 이 영역을 **검사하지 않는다** — `macos/` 만 바뀌면 backend·frontend·e2e·hooks 가
전부 SKIPPED 다. 초록을 검증으로 읽지 말 것. 실제 검증은 로컬에서 한다.

    cd macos && swift build -c release        # 빌드
    ./macos/build-app.sh install              # 설치
    curl -s http://127.0.0.1:7777/api/sessions | python3 -m json.tool | head
    lsof -nP -iTCP:7777 -sTCP:LISTEN          # 127.0.0.1 이어야 한다

접근성 권한이 없으면 osascript 자동 클릭이 `-25211` 로 막힌다.
그때는 **앱이 스스로 말하게** 한다 — stderr 로그를 심고 앱을 로그 리다이렉트로 띄운다.
(원인을 찾은 뒤에는 반드시 제거할 것. 릴리스 바이너리에 남기지 않는다.)

## 남은 것 / 안 한 것

- **세션 종료·재개 버튼** — 넣지 않는다 ([00-개요](00-개요.md) 범위 밖). 복사까지가 선이다
- **ppid** — 백엔드가 주지 않는다. 세션을 죽이는 목적에는 `pid` 로 충분해서
  `collect/` 를 건드리지 않았다. 필요해지면 그때 수집부를 고친다
- **높이 상수(행 20pt · 그룹 헤더 29pt)** — 폰트 크기에서 계산한 추정치다.
  폰트를 바꾸면 다시 재야 한다
- **아이콘·다크모드 대응** — 손대지 않았다. 시스템 기본을 따른다

## 조사했고 "못 한다"로 끝난 것 (2026-09-04)

같은 것을 다시 파헤치지 않도록 **근거와 함께** 남긴다.

### GPT(ChatGPT 앱)의 컨텍스트·사용량 — 불가능

사용자는 ChatGPT를 **앱으로만** 쓰고 Codex는 쓰지 않는다. 대화는 OpenAI 서버에 있고
로컬에는 읽을 것이 없다.

```
~/Library/Application Support/com.openai.chat/   164KB   ← 캐시뿐
~/.codex/sessions/*.jsonl                        50개
```

`~/.codex` 쪽 jsonl 에 `token_count` · `rate_limits` **구조는 있지만 값이 전부 `null`**
이다(50개 전수 확인). 앱 설치 시 만들어진 껍데기라 앞으로도 채워지지 않는다.

```bash
# 재현: rate_limits 에 값이 있는 세션 수 → 0
python3 -c "
import json,pathlib
n=0
for f in pathlib.Path.home().joinpath('.codex/sessions').rglob('*.jsonl'):
    for l in f.read_text(errors='ignore').splitlines():
        if '"rate_limits"' in l and json.loads(l).get('payload',{}).get('rate_limits'): n+=1; break
print(n)"
```

### Claude 사용량(%·리셋까지 남은 시간) — 로컬에 없다

세 곳 모두 비어 있다:

| 확인처 | 결과 |
|---|---|
| 세션 jsonl | `rate_limit`/`resets` 매칭 **0줄** |
| `~/.claude.json` | `hasAvailableSubscription` 뿐, 사용률·리셋 없음 |
| `claude` CLI · `claude doctor` | `usage`/`cost`/`limit` 명령 없음 |

사용량은 API 응답 헤더로만 오고 디스크에 남지 않는다. 표시하려면 앱이
`api.anthropic.com` 에 주기적으로 요청해야 하는데, 그것은
[00-개요](00-개요.md) 절대 원칙(*"데이터는 이 기계를 떠나지 않는다,
백엔드는 `127.0.0.1` 에만 바인딩"*)을 넘는다.

**넣지 않기로 했다.** 세션에서 `/usage` 를 치면 5시간·주간 한도와 리셋 시각이
정확히 나오고, 메뉴바에 넣어 얻는 것은 "치는 수고 하나" 정도인데
원칙에 구멍을 내는 비용이 더 크다. 나중에 넣는다면 **원칙의 예외를
`docs/00-개요.md` 에 명시하는 것이 먼저다** — 조용히 추가하지 말 것.
