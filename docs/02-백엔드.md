# 02. 백엔드

## 스택

| | 선택 | 이유 |
|---|---|---|
| 런타임 | Node 20+ | `npm i -g` 배포가 가장 쉬움 |
| 언어 | TypeScript | |
| HTTP | **Hono** | 가볍고 Node 네이티브. NestJS 는 로컬 도구에 과함 |
| 린터 | **Biome** | 기존 프로젝트와 동일 |
| 테스트 | **Vitest** | |

프론트는 빌드 결과를 백엔드가 정적 서빙한다. 배포 산출물이 패키지 하나가 되어
설치·실행이 단순해진다.

## 파일 구조

```
claude-board/
├── package.json
├── tsconfig.json
├── biome.json
├── src/
│   ├── cli.ts                 # 진입점. 포트 선택·서버 기동·브라우저 열기
│   ├── server.ts              # Hono 앱. 127.0.0.1 바인딩
│   ├── api/
│   │   └── sessions.ts        # GET /api/sessions, GET /api/stream
│   ├── collect/
│   │   ├── agents.ts          # `claude agents --json` 실행·파싱
│   │   ├── transcript.ts      # jsonl 역순 리더 (핵심)
│   │   ├── state.ts           # 상태 판별 규칙
│   │   └── aggregate.ts       # 프로젝트 단위 집계
│   └── types.ts
├── web/                       # 프론트 (03-프론트.md)
└── docs/
```

### 역순 리더 — `collect/transcript.ts`

가장 중요한 모듈. 5.8MB 파일을 전부 읽으면 안 된다.

```
파일 끝에서 64KB 씩 뒤로 읽으며 줄 단위로 역순 순회
필요한 필드(aiTitle · lastPrompt · gitBranch · permissionMode · usage · 마지막 대화 레코드)를
모두 채우면 즉시 중단
64KB 를 다 훑어도 못 채우면 다음 청크로 확장 (상한 1MB, 넘으면 포기하고 부분 결과 반환)
```

부분 결과라도 반환한다. 제목이 없어도 상태 판별은 되게 할 것.

### `GET /api/stream` (SSE)

5초 간격으로 위와 동일한 페이로드를 push.
간격은 `--interval` 로 조정 가능하게.

## CLI

```bash
claude-board                    # 서버 기동 + 브라우저 열기
claude-board --port 7777
claude-board --no-open
claude-board --json             # 1회 수집 결과를 stdout 으로. 검증·디버깅용
claude-board --interval 10
```

`--json` 을 **먼저 만든다.** 프론트 없이 `curl`/`jq` 로 데이터 모델을 검증할 수 있고,
[05-검증](05-검증.md) 의 절차가 여기에 의존한다.

## 구현 순서

1. `types.ts` — 타입부터 확정
2. `collect/agents.ts` — `claude agents --json` 파싱
3. `collect/transcript.ts` — 역순 리더 + 단위 테스트
4. `collect/state.ts` — 상태 판별 + 단위 테스트 (**tool_result 오인 케이스 반드시 포함**)
5. `collect/aggregate.ts` — 프로젝트 집계
6. `cli.ts --json` — 여기서 [05-검증](05-검증.md) 1~3 수행
7. `server.ts` + `api/` — HTTP 노출
8. 프론트 ([03-프론트](03-프론트.md))

6번까지 끝나면 데이터 모델이 검증된다. 프론트는 그 다음이다.
