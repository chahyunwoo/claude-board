# 02. 백엔드

## 스택

| | 선택 | 이유 |
|---|---|---|
| 언어 | **Java 21** | record · pattern matching · virtual thread 사용 가능 |
| 프레임워크 | **Spring Boot 3** | 실무 스택. 이 도구가 요구하는 것들이 Spring 실무 패턴과 겹친다 |
| 빌드 | **Gradle (Kotlin DSL)** | |
| 테스트 | **JUnit 5 + AssertJ** | |

### 왜 Spring 인가 — 이 프로젝트가 요구하는 것들

억지 근거가 아니라 실제로 겹친다.

| 이 도구에 필요한 것 | Spring 요소 |
|---|---|
| 5초마다 세션 수집 | `@Scheduled` |
| 실시간 갱신 | `SseEmitter` |
| `claude agents --json` 실행 | `ProcessBuilder` |
| 5.8MB 파일 역순 읽기 | NIO `FileChannel` / `RandomAccessFile` |
| 상태 판별 | 순수 도메인 로직 + JUnit |
| API 스키마 | `record` DTO |

### 포기하는 것 (알고 간다)

```
설치:  npm i -g 한 줄  →  ./gradlew bootRun 또는 jar
기동:  ~100ms          →  JVM 부팅
전제:  없음             →  JDK 21 필요
```

개인 도구로 쓰는 동안엔 실질 문제가 아니다.
남에게 배포할 단계가 오면 GraalVM native-image 를 검토한다 ([04-배포](04-배포.md)).

**`collect/` 는 Spring 에 의존하지 않게 짠다.** 순수 자바 클래스로 두면
단위 테스트가 빠르고, 나중에 다른 곳으로 옮겨도 그대로 간다.

## 핵심 — `TranscriptReader`

5.8MB 파일을 전부 읽으면 안 된다.

```
파일 끝에서 64KB 씩 뒤로 읽으며 줄 단위 역순 순회
필요한 필드(aiTitle · lastPrompt · gitBranch · permissionMode · model · usage
             · 마지막 대화 레코드)를 모두 채우면 즉시 중단
64KB 로 못 채우면 다음 청크로 확장. 상한 1MB, 넘으면 부분 결과 반환
```

부분 결과라도 반환한다. 제목이 없어도 상태 판별은 되어야 한다.

`FileChannel.map()` 또는 `RandomAccessFile.seek()` 을 쓴다.
JSON 파싱은 Jackson `ObjectMapper.readTree()` 로 줄 단위.

## 설정

`application.yml`
```yaml
server:
  address: 127.0.0.1        # 반드시. 0.0.0.0 금지
  port: 7777

claude-board:
  interval: 5s              # 수집 주기
  stalled-after: 10m        # 멈춤 의심 임계
  idle-after: 2h            # 유휴 임계
  context-limit: 1000000    # 컨텍스트 상한 기본값. 관측값이 넘으면 자동 상향
  transcript-max-bytes: 1MB # 역순 읽기 상한
```

## 컨텍스트 상한 — 주의

세션 기록의 모델명은 `claude-opus-5` 로만 남고 **`[1m]` 변형이 구분되지 않는다.**
실측에서 671,229 토큰이 관측됐으므로 그 세션은 1M 모델인데 기록으로는 알 수 없다.

→ 설정의 `context-limit` 을 기본값으로 쓰되,
**관측 토큰이 그 값을 넘으면 상한을 자동으로 올린다.**
표시는 `절대값 / 상한 · %` 세 가지를 모두 낸다 (분모가 틀려도 절대값으로 판단 가능).

## 구현 순서

1. `domain/` — record 와 enum 부터 확정
2. `collect/AgentsReader` — `ProcessBuilder` 로 CLI 실행
3. `collect/TranscriptReader` — 역순 리더 + 단위 테스트
4. `collect/StateResolver` — 상태 판별 + 단위 테스트 (**tool_result 오인 케이스 필수**)
5. `collect/Aggregator` — 프로젝트 집계
6. CLI 모드 (`--json`) 또는 테스트로 [05-검증](05-검증.md) 1~3 수행
7. `web/` — HTTP 노출
8. 프론트 ([03-프론트](03-프론트.md))

6번까지 끝나면 데이터 모델이 검증된다. 프론트는 그 다음이다.
